# bible-taxonomy

A learning path and knowledge graph for teaching and learning the Bible, modelled on [`os-taxonomy`](../os-taxonomy) (Marble's UK-standards skill graph). Learners move from simple Bible stories to doctrine, following prerequisite links, and see how every story fits into covenant history.

## Motivation
- **Scripture is the authority.** The ESV is the ultimate authority; the KJV is also accepted. Teachers (Luther, Calvin, Spurgeon, Sproul, Baucham and others) and confessions are *supplements* that help explain the deeper meaning of chapters and verses and how stories fit the covenant story. They never override the text.
- **Exactness over volume.** Every reference is an exact book, chapter and verse, checked by machine against the KJV text. Nothing is made up: no invented quotes, page numbers, dates or links.
- **A graph, not a list.** Topics have prerequisites (what to learn first) and typed relations (e.g. an Old Testament text quoted in the New), each justified by cited scripture.

## Layout
| Path | Purpose |
|---|---|
| `data/kjv.json` | KJV text keyed `BOOK.chapter.verse` (USFM book codes: `GEN`, `ROM`, `1CO`...). Generated by `scripts/import-kjv.mjs` from `sources/kjv/pg10.txt` |
| `data/topics.json` | Nodes: `STORY`, `DOCTRINE`, `BOOK_OVERVIEW`, `THEME`, `COVENANT`, `SKILL` (`bt_` ids) |
| `data/dependencies.json` | Prerequisite DAG. `topicId` depends on `prerequisiteId`; strength `hard`/`soft` plus a reason |
| `data/relations.json` | Typed edges (`fulfilled-in`, `quoted-in`, `parallels`, `part-of-covenant`, `illustrates-doctrine`); each must cite scripture |
| `data/covenants.json` | Covenant spine (`cv_` ids): creation, Noah, Abraham, Moses, David, new. Topics link via `covenant` |
| `data/teachers.json`, `works.json`, `citations.json` | Source of truth for teacher tracking (bibliographic only) |
| `TEACHERS.md` | Generated authors / works / timeline file. Do not edit by hand |
| `sermons/` | Raw transcripts to be synthesized. See `sermons/README.md` |
| `confessions/` | e.g. Second London Baptist Confession (1689). See `confessions/README.md` |
| `catechisms/` | Including children's catechisms. See `catechisms/README.md` |
| `schema/` | JSON Schemas for each data file |
| `fragments/` | Parallel authoring: write a fragment, `node scripts/fragment.mjs check <file>`, then a maintainer merges. `scripts/show.mjs` prints KJV passages |
| `scripts/` | `validate.mjs`, `import-kjv.mjs`, `build-teachers-md.mjs`, `fragment.mjs`, `show.mjs` |

```
npm run validate                          # integrity checks
node scripts/validate.mjs --update-manifest   # after editing data, refresh checksums
npm run build:teachers                    # regenerate TEACHERS.md
```

## Passage references
A reference is `{book, chapter, verseStart, verseEnd}` within one chapter; multi-chapter passages are several refs. In text and front matter: `ROM.5.12-21`. ESV links are derived from refs, never stored (e.g. `https://www.esv.org/Romans+5/`); ESV text is not stored (Crossway copyright).

## For agents
1. **Never fabricate.** If you can't verify a reference, quote, date or URL from a source in this repo or a fetched page, leave it out.
2. **Scripture text comes only from `data/kjv.json`.** Don't type verses from memory. Don't reproduce ESV text.
3. **Teachers are bibliographic only**: author, work, year, edition, exact location, URL, passages addressed. No quoted or paraphrased teacher text. New citations get `verified: false`; a human sets `true` plus `verifiedOn`.
4. **Add content through the data files**, then run `node scripts/validate.mjs --update-manifest` and `npm run validate`. It must pass. It checks references against real KJV verse bounds, rejects prerequisite cycles, requires scripture on every relation, and checks front matter in `sermons/`, `confessions/`, `catechisms/`.
5. **Turn sermon transcripts into curriculum** only via the workflow in `sermons/README.md`.
6. Each topic needs: exact `primaryPassages`, `evidence` (what a learner can do) and an `assessmentPrompt` using `{{name}}` as the child-name placeholder (as in os-taxonomy; substitute or strip before display).
